# Actor-Based SRP and Clean-Code Audit

## Summary

- **Seventh pass (OJS-GO-073):** workflow creation still emitted a root `options` object and job-level `meta`/synthetic topology fields that are absent from the shared backend `WorkflowRequest`/`WorkflowJobRequest`. Defaults are now resolved once and fully materialized into each chain step, group/batch job, and callback `options`; metadata is a shallow key merge under `options.metadata`, with per-job keys winning and nested values replaced atomically. A strict local mirror of the shared backend types rejects unknown fields without importing the sibling module.
- **Seventh pass (OJS-GO-074):** the exported workflow response omitted backend fields needed to understand primitive type, progress, callbacks, and completion. `Workflow` now decodes `type`, chain/job totals and completions, callbacks, and `completed_at` while retaining `Steps` and the cancel-response fields; callback args/options are preserved as raw JSON.
- **Seventh pass (OJS-GO-075):** enqueue timeout used zero as both "unset" and "explicitly disabled", so `WithTimeout(0)` disappeared and could not override a workflow default. Private presence tracking now distinguishes unset, zero, and nonzero values for both direct enqueue and materialized workflow jobs.
- **Seventh pass (OJS-GO-076):** grace-expiry NACKs were sequential, so one hung report prevented every later active job from being attempted. A fixed-size worker pool now gives each claimed job exactly one NACK call under the shared deadline, preserves the existing exactly-once claim barrier, and logs collected failures in sorted job-ID order.
- **Sixth pass (OJS-GO-071):** `DurableContext.StateRaw` returned the mutex-protected internal `json.RawMessage` slice directly, and `LoadState` retained the same backing array after unlocking. A caller could mutate checkpoint state without the mutex or race JSON decoding. Both methods now clone under the lock; decoding happens from `LoadState`'s private copy after release.
- **Sixth pass (OJS-GO-072):** `federation.NewFromConfig` silently treated a negative `FailureThreshold` like zero and fell back to the default, even though the direct option rejects negatives. The declarative boundary now rejects negative values with config and value context; zero remains the documented default sentinel and positive values still apply the option.
- **Fifth pass (OJS-GO-069):** the non-idempotent retry fix also suppressed HTTP 429 for POST, even when the server returned a valid `Retry-After` instruction. A valid `Retry-After` on 429 is now evaluated before the safe/idempotent operation gate for every method, while ambiguous 502/503/504 and non-pre-dial connection failures remain suppressed for POST; retry budgets and context cancellation still bound the exception.
- **Fifth pass (OJS-GO-070):** enqueue priority used zero as both "unset" and "explicitly set to zero", so `WithPriority(0)` disappeared from JSON and could not override a nonzero workflow default. The private enqueue config and wire options now retain presence separately from value; unset priority is omitted, while explicit zero and nonzero priorities are emitted and merge in normal option order without changing the public functional-option API.
- **Fourth pass (OJS-GO-066):** every serverless HTTP push entry point accepted unsigned requests and decoded/executed them without authenticating the OJS producer. Shared push handling now reads a bounded raw body, verifies `X-OJS-Timestamp` plus one or more `sha256=` HMAC-SHA256 signatures in constant time before decoding, enforces a ±5 minute default freshness window, supports multiple secrets/signatures for rotation, bounds authentication headers, and fails closed when no secret is configured unless an explicitly insecure local-development option is selected.
- **Fourth pass (OJS-GO-067, corrected by OJS-GO-073):** the previous metadata fix emitted client job metadata as unsupported workflow-root `meta`. Metadata was subsequently materialized per job, and the seventh pass completed the shared-binding alignment by placing it under each job's `options.metadata` and removing root `options`.
- **Fourth pass (OJS-GO-068):** group validation required two jobs even though the workflow schema declares `jobs.minItems: 1`. Single-job groups are now accepted and emitted normally; empty groups still fail locally with a precise minimum-one error.
- **Third pass (OJS-GO-061, corrected by OJS-GO-073):** the workflow request wire flattened chain, group, and batch into one synthetic `steps` array. Requests now carry the discriminated shared-backend shape (`type` plus `steps`/`jobs`/`callbacks`), with chain order represented by array position and no synthetic request IDs or dependency edges.
- **Third pass (OJS-GO-062):** `DurableContext` decoded a resumed checkpoint's `step_index` and application `state` only to feed a legacy-migration write, then discarded both. A handler that checkpoints application-level progress via `Checkpoint(stepIndex, state)` — rather than inferring progress purely from `Now`/`Random`/`SideEffect` replay — had no way to learn where to resume and always restarted its pipeline from step zero. Both values are now retained and exposed via `HasCheckpoint`, `StepIndex`, `StateRaw`, and `LoadState`, for canonical and migrated-legacy checkpoints alike.
- **Third pass (OJS-GO-063):** the transport retried 429/502/503/504 for every HTTP request regardless of method or operation, so a lost response after the server had already committed a non-idempotent write -- enqueue, batch enqueue, workflow creation, worker fetch/ack/nack/heartbeat, durable checkpoint save -- would be silently retried into a duplicate action. Retry eligibility is now derived from the HTTP method (GET/HEAD/DELETE/PUT eligible, POST not, by default) with an explicit `postIdempotent` opt-in for the two POST operations actually vetted as safe (queue pause/resume); a new connection-error path retries only a provably pre-dial failure (nothing was ever transmitted) or an already-eligible operation.
- **Third pass (OJS-GO-064):** `attest.PQCOnlyAttestor` signed and verified a bare `SHA256(ArgsHash || ResultHash || Timestamp)` digest, and derived its "nonce" from that same digest -- fully predictable from identical input, not random, and covering none of the receipt's other claimed fields (JobID, Jurisdiction, ModelFingerprint, KeyID, quote type). `Verify` checked only that a signature matched whatever bytes `Quote.Evidence` happened to hold, so a valid (evidence, signature) pair could be transplanted onto a receipt claiming a different job, and nothing bounded how old a receipt could be. `Attest` now draws a fresh crypto-random nonce every call and signs a versioned canonical evidence payload covering every field the finding calls for; `Verify` parses and requires that version, cross-checks the receipt's own claims against it field by field, validates algorithm/key ID and nonce format, checks timestamp consistency and freshness, and only then checks the signature -- rejecting tampering, transplant, replay-by-staleness, and the legacy digest-only shape outright.
- **Third pass (OJS-GO-065):** `workerLifecycle`'s terminate transition was only absorbing on paper: `applyServerDirective` read the current state, decided a directive was legal, and only *then* wrote it, with no lock spanning both steps, and `set` (the local-shutdown entry into terminate) wrote unconditionally. A server-directed quiet/running directive that read the state as non-terminate could still write it after a concurrent local shutdown had already entered terminate, clobbering it back. The read-decide-write sequence in both is now one critical section under a single mutex, making terminate truly absorbing: whichever call reaches it first, every concurrent or later call — quiet, running, or another shutdown — observes it and refuses to move away.
- **Second pass (OJS-GO-055 to 060):** the worker's shutdown story was completed. A server-directed `terminate` was accepted into the lifecycle and then ignored — it stopped fetching and nothing else — and the grace-period sweep could NACK a job whose handler was simultaneously ACKing it. Terminate now enters exactly the caller-cancellation drain path, and every job reports exactly one terminal outcome behind a grace-expiry claim barrier; reports claimed before the barrier finish on bounded contexts, while later completions lose to the forced NACK.
- **Second pass, continued:** OJS-GO-054's move to the standard checkpoint resource had no read path for what the previous release wrote, so an in-flight durable job lost its replay log across an SDK upgrade and re-ran every recorded side effect. The legacy endpoint and encoding are now read, replayed exactly, and migrated forward to the canonical v1 state.
- **Second pass, continued:** two more silent-drop defects of the same class as OJS-GO-002/003/005: `meta` was excluded from workflow override detection *and* absent from the workflow wire, discarding `WithMeta` and every `ext_*` extension for all four step kinds; and any args array merely *starting* with an object collapsed to that object, deleting the rest on re-encode.
- **Highest-leverage fix:** the worker reported job outcomes on the same context it cancels at shutdown, so every ACK/NACK issued during the graceful-drain window failed instantly and completed jobs were silently re-run by the server. Reporting now uses a shutdown-surviving context, locked by a regression test that fails against the previous code.
- **Highest-leverage split:** `worker.go` (648 lines) carried five distinct actors. It remains orchestration-only (currently 667 lines after the complete shutdown state machine and forced-report implementation), with the worker-protocol wire binding, lifecycle state, in-flight bookkeeping, and handler-facing context owned by named units.
- The red staticcheck baseline (`checkpointState` unused, `errors.As` simplification, nil-map length check, four nil-context test calls) is reproduced and fixed at the cause, not suppressed. `staticcheck ./...` is clean on all three modules.
- One red test was reproduced: `TestPropertyValidJobTypesAlwaysAccepted` asserted that `"my-job"` is a valid job type. The normative spec and the shared conformance corpus both forbid hyphens, so the **test** was wrong and the validator was right; the assertion was corrected and the rule locked by a new rejection test.
- Silent option drops were the dominant class of real defect: workflow group/batch/callback steps discarded per-step options entirely, workflow-level options were emitted only when queue or timeout changed, and `WithLabels`/`WithWorkerCapabilities` were stored but never transmitted. All are now mapped and covered.
- The configured `golangci-lint v1.64.8` gate is now **green at zero findings on all three modules**. It was red, and the report was also being silently truncated: golangci-lint's default `max-issues-per-linter: 50` capped `gocritic` at exactly 50, hiding the rest. Reporting is now uncapped, which raised the true baseline before any of it was fixed.
- One deliberate lint-policy exception was taken: `gocritic hugeParam` only. Everything else in the `performance` tag — `rangeValCopy` included — stays enabled and was fixed to zero. The rationale and the exact API constraints are recorded in `.golangci.yml` next to the setting.
- All 76 repository-local findings are implemented. The two deferred items are control of the external reusable CI workflow (lives in `openjobspec/.github`) and a `grpc`-module dependency upgrade whose fix requires raising that module's minimum Go version -- a decision outside this pass's assigned findings; see "Deferred".
- Public API compatibility is preserved: module-mode `apidiff` against the `HEAD` baseline reports compatible additions only. OJS-GO-074 adds fields to `Workflow` plus the two callback response types; the earlier compatible serverless, durable, attestation, worker, and context additions remain. There are zero removals or signature changes, and the `grpc` and `middleware/otel` module APIs are unchanged.

## Structural coverage

Every Go file over 150 lines and every `Manager`/`Helper`/`Utils`/`Service`/`Handler` declaration was inventoried. Root, `grpc`, and `middleware/otel` were each built, tested, vetted, staticchecked, and golangci-linted independently with `GOWORK=off`.

| `.../ojs-go-sdk/middleware/otel` | `middleware/otel/go.mod` | 1.24.0 | `ojs-go-sdk => ../../` (pre-existing; standard nested-module self-reference) | yes |

No local replace was added. Both nested modules had incomplete `go.sum` files and could not build, vet, or staticcheck at all before `go mod tidy`; that is recorded as OJS-GO-014.

## Assumptions

- A server-directed `terminate` means the same thing as `SIGTERM`: the worker protocol lists both as triggers for the identical transition, so they must not have two shutdown implementations. `quiet` is deliberately *not* observable as a shutdown edge, because `quiet -> running` is a legal transition and a worker released from quiet must keep running.
- Under grace-period expiry the graceful-shutdown spec's force-stop phase says active jobs are abandoned, so `Start` force-NACKs their jobs and returns rather than waiting on a handler that ignored cancellation. Waiting would let one handler hold a rolling restart open indefinitely.
- A forced NACK and a handler ACK for the same job are contradictory, not merely redundant, so exactly one must win. Grace expiry first closes the handler-claim gate, then force-claims the remainder. A handler that claimed before the gate closed keeps a five-second reporting context and is joined; a handler completing afterward is logged and discarded.
- A legacy checkpoint that cannot be reached or decoded is treated like OJS-GO-033's failed load: an error that stops the handler, because the alternative is re-running recorded side effects. Only 404 and 405 from the legacy endpoint mean "this server never served it", which is the same no-checkpoint result the spec defines for the standard resource.
- Migrating a recovered legacy checkpoint forward is best-effort and never a reason to fail a job: the replay log is already in hand, so replay is exact either way. The failure is surfaced by the new `MigrationError` accessor rather than discarded, and the legacy checkpoint is left in place rather than deleted, so a failed migration loses nothing.
- The single-job enqueue binding keeps `meta` beside `options`, but the shared workflow binding uses `WorkflowJobRequest.Options.Metadata` and has neither root enqueue options nor job-level meta. Workflow defaults therefore have to be materialized into every job/callback options object; per-job metadata keys are copied afterward and override defaults.
- An args array of exactly one object is the only shape the `Args` map can represent without loss, so it is the only shape that maps to it. `[{"a":1},2,3]` is positional args that happen to start with an object; treating it as the map form is what deleted the tail. `[{}]` is one empty argument and is not the same wire value as `[]`.
- The OJS specification under `spec/` and the conformance corpus under `ojs-json-schema/` are normative when a test and the spec disagree; this decided OJS-GO-026 in favour of the validator.
- Adding optional, `omitempty` fields to worker requests is compatible: servers ignore unknown fields, and the payload is byte-identical when the corresponding options are unset (proved by `TestHeartbeatOmitsUnsetLabelsAndCapabilities`).
- `middleware/otel` may rely on the new `JobContext.WithContext` because its `go.mod` already carries the standard nested-module replace to the repository root, so the two always build together.
- `gofmt` compliance is a baseline expectation for a Go SDK, so the mechanical whitespace normalisation of 23 pre-existing files is acceptable alongside behavioural work.
- A cross-region federation identifier is security-relevant: it correlates a job across regions and travels in peer requests, so it must come from a CSPRNG. That decided OJS-GO-045 in favour of `crypto/rand` over any `math/rand` variant, which `gosec` flags identically anyway.
- `generateFederationID` is unexported and no test or wire contract pinned its bytes — only its uniqueness — so moving it to a real UUIDv7 layout is an internal change. The output is still a canonical 8-4-4-4-12 UUID string.
- Turning a panic into an error (OJS-GO-039) is a compatible improvement: no caller can have depended on `Attest`/`Verify` crashing the process on a malformed key.
- `crypto/rand.Read` is documented never to fail as of Go 1.24, which the root `go.mod` requires. The error branches kept around it are contract statements, not reachable paths; where a fallback exists it is the conservative one (full backoff, never a shorter wait).
- `gocritic hugeParam` is advisory rather than a correctness rule, so suppressing exactly that check is preferable to breaking `HandlerFunc`, the `Attestor` interface, or the fluent builders — all of which are load-bearing published API.
- Request and response workflow bindings are intentionally separate: outbound jobs match shared `WorkflowJobRequest` (type/args/options, chain order by array position), while inbound `WorkflowStep` retains server-generated IDs, dependencies, timestamps, state, and result data.
- `WorkflowDefinition.Options` retains its documented meaning ("default enqueue options for all steps"), but the shared request has no root options field. `CreateWorkflow` resolves definition and call-site defaults once, then materializes the result into every job/callback; per-job options override that effective config without mutating either option source.
- Metadata merge is shallow by top-level key. This is deliberate for opaque extension payloads: a per-job nested `ext_*` object replaces the corresponding default object whole, avoiding undocumented recursive semantics while preserving the nested JSON value unchanged.
- `HasCheckpoint()` is deliberately independent of `IsReplaying()`: the latter is about whether the Now/Random/SideEffect cursor has unreplayed entries, while the former is about whether a checkpoint exists at all. A checkpoint written by a handler that only ever calls `Checkpoint(stepIndex, state)` has an empty replay log (`IsReplaying() == false`) but must still report `HasCheckpoint() == true` and the correct `StepIndex`, or a step-driven handler could never resume.
- `LoadState` returns nil rather than an error when there is nothing to load (no checkpoint, or a checkpoint with no state), leaving `target` untouched: this keeps the common `var st T; dc.LoadState(&st)` call unconditional for callers who structure resume logic entirely around `StepIndex`, without forcing every caller to branch on `HasCheckpoint` first merely to decode state. Callers that must distinguish "loaded the zero value" from "nothing to load" still can, via `HasCheckpoint`.
- `StateRaw` transfers byte ownership to its caller rather than exposing `DurableContext` storage. Returning a defensive copy preserves the method's value semantics while making the existing mutex meaningful after return; `LoadState` likewise must not retain an internal slice alias across unlock merely because JSON decoding itself happens outside the critical section.
- `FederationConfig.FailureThreshold == 0` remains an unset/default sentinel, matching the method's pre-existing `> 0` translation and the other optional duration fields. Negative values are invalid rather than another spelling of default because `WithFailureThreshold` already defines the public threshold domain as non-negative.
- The worker's pre-existing `ackJobWithRetry`/`nackHandlerErrorWithRetry` (an application-level retry loop scoped to a single job ID the worker already owns, covered by `worker_retry_test.go` before this pass) is a distinct, deliberate mechanism from the transport-level classification OJS-GO-063 adds, and is unaffected by it: it re-invokes `ackJob`/`nackJob` as whole new calls on its own schedule, and each individual call is still subject to the transport's per-call retry decision (which now correctly does not retry a transient status within that single call). The finding's "never automatically retry ... ack/nack" is about that per-call transport behavior, not about removing the worker's own outcome-delivery retry.
- Every DELETE this SDK issues (job/workflow cancellation, checkpoint/dead-letter/cron removal) and PUT (unused today, included for symmetry with the finding's explicit "idempotent PUT/DELETE") are treated as unconditionally retry-eligible: each reaches the identical end state whether it runs once or twice, so no per-operation review was needed the way POST required. `RegisterCronJob` and `RetryDeadLetterJob` stay on the non-retried POST default alongside enqueue/fetch/ack/nack/heartbeat/workflow-creation/checkpoint-save: registering a schedule or re-queuing a dead-letter job is a create/action operation with no idempotency key, the same class of risk as enqueue.
- A pre-dial connection failure (`*net.OpError` with `Op == "dial"`) is retried for every operation, including a non-idempotent one, because it is the one connection-level failure this SDK can prove happened before any request bytes were transmitted -- DNS failures are wrapped the same way by `net/http`. Every other connection failure (a write that failed partway, a read timeout, a reset after bytes were sent) cannot be told apart from "the server received and processed the request but the response was lost," so it follows the operation's existing retryEligible classification instead.
- `progress_test.go`'s pre-existing unreachable-host case now disables retries explicitly (`RetryConfig{Enabled: false}`) rather than relying on the SDK never retrying a connection failure: that case predates and is unrelated to OJS-GO-063's classification (progress reporting is itself a non-retry-eligible POST), and disabling retries keeps the test's original fail-fast timing intent explicit instead of incidental.
- A stateless `Verify(ctx, receipt) error` call has no nonce registry or datastore to consult, so "reject ... replay-invalid receipts" is implemented as a bounded freshness window (`DefaultMaxReceiptAge`, 24h) on the signed quote-issuance timestamp: a receipt older than that is treated the same as a replayed one. True exactly-once replay prevention would require a caller-supplied, persistent nonce registry, which no part of this finding or the existing `Attestor` interface provides for; that is recorded as a follow-up rather than invented as an unrequested storage dependency in a Labs package documented as dependency-free.
- Ed25519 signs arbitrary-length messages directly, so the canonical evidence payload is signed as its full JSON encoding rather than a SHA-256 digest of it: this makes `Quote.Evidence` self-describing (a verifier -- or an operator debugging a rejected receipt -- can decode it directly) and removes a hashing step that added nothing Ed25519 needed. `encoding/json`'s struct-field marshal order is declaration order, not map/alphabetical order, so encoding a fixed struct (no maps) is deterministic without a custom canonicalization scheme.
- `NoneAttestor` is unchanged beyond forwarding the new optional `Jurisdiction`/`ModelFingerprint` input fields onto its result for API consistency: it is documented as the explicit "attestation disabled" no-op and makes no cryptographic claim for `Verify` to strengthen, so it is exempt from the canonical-evidence version boundary the package doc now states for signing attestors.
- `AttestInput.Jurisdiction`/`ModelFingerprint`, `Receipt.JobType`/`ArgsHash`/`ResultHash`, `NewReceipt`, and `PQCOnlyAttestor.MaxReceiptAge` are additions only: every previously exported field, method, and constructor signature is unchanged, and a caller who does not set the new `AttestInput` fields or touch the new `Receipt` fields sees `nil`/zero-value behavior equivalent to before this pass (proved by the updated pre-existing tests, which needed only to switch from hand-built `Receipt{...}` literals to `NewReceipt`, not to change what they assert).
- A mutex was chosen over an `atomic.Value` compare-and-swap loop (the finding's other sanctioned option): lifecycle transitions happen at heartbeat frequency at most (every few seconds) plus once at shutdown, so there is no performance case for a lock-free CAS retry loop, and a single critical section spanning the read, the validity decision, and the write is simpler to verify correct by inspection than a CAS loop's retry-on-conflict logic, which would also have needed a defined behavior for a `workerLifecycle` whose `atomic.Value` was never stored to (only reachable via a hypothetical bare struct literal; `currentLocked`'s empty-state fallback keeps that same leniency without the CAS complication).
- `workerLifecycle.state`'s field type and the exported `WorkerState` constants are unchanged; only the private storage mechanism (`atomic.Value` -> mutex-guarded field) changed, so this is an internal correctness fix with no public API impact, matching how OJS-GO-004's middleware-chain race was fixed with a `sync.RWMutex` in the earlier pass.
- Serverless adapters previously had no implicit environment configuration, so push secrets remain explicit options rather than adding surprising process-global reads. Deployment examples load their platform secret into the option; an empty environment value is ignored and therefore leaves the endpoint fail-closed. Replay protection follows the webhook specification's bounded timestamp window; exact once-only delivery-ID storage would require shared persistent state that serverless handlers do not currently own.
- A syntactically valid `Retry-After` is treated as the server distinguishing throttling from an ambiguous transient failure, so it may override the method gate for 429 only. Missing or malformed `Retry-After` on a non-idempotent POST remains non-retryable; 5xx and ambiguous connection failures are unchanged.
- Priority zero is a meaningful workflow override rather than a default sentinel. Presence therefore belongs to the private option-resolution/wire layer; the public `WithPriority(int)` signature remains unchanged and callers do not need a pointer-valued API.
